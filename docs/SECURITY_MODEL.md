# Anas 安全模型与审批原则

> 状态：项目级规范，审计、设计和实现必须遵守
> 生效日期：2026-08-09
> 最近修订：2026-09-25
> 适用范围：主进程、Renderer、preload、Agent runtime、工具、Skill、MCP、附件、备份、配置与发布链路

## 1. 规范地位

本文档是 Anas 安全边界、威胁分类和审批策略的唯一真相源。

- 开始安全审核、权限设计、工具接入或破坏性操作改造前，必须先阅读本文档；
- 审计结论必须明确说明问题是否落在本文档定义的威胁模型内；
- 不能仅因通用桌面应用、浏览器沙箱或云端多租户的安全惯例而扩大本项目威胁模型；
- 若新的产品需求与本文档冲突，先修改本文档并记录产品决定，再调整实现和审计结论；
- 修复台账、代码注释和测试不得建立与本文档并行或相反的安全模型。

## 2. 产品定位

Anas 是运行在用户桌面上的本地 Agent 系统。Agent 代表当前用户主动完成任务，是拥有实际执行能力的协作者，不是敌对租户或仅能提出建议的聊天机器人。

为完成用户目标，Agent 可以按配置和任务上下文主动：

- 阅读、创建、修改、移动和删除文件；
- 访问公网、私网和本机服务；
- 使用用户配置的凭据调用服务；
- 调用 MCP、内置工具和外部程序；
- 创建、修改和执行 Skill 脚本；
- 将完成任务所需的数据传递给模型提供商或目标服务。

这些能力本身不是安全漏洞。安全机制的目标是让 Agent 的实际效果与用户目标一致，并降低程序缺陷、参数错误、陈旧状态或目标歧义造成的意外损坏。

## 3. 信任边界

### 3.1 默认受信任

- 用户选择的模型及模型提供商；
- Agent 为完成用户目标形成的意图、推理和工具选择；
- 当前登录的操作系统用户、本地 Anas 应用进程及安装目录；
- 用户明确启用的工具、MCP 服务、Skill 和项目；
- 为完成明确目标而有意执行的宿主命令、网络访问和数据传递。

“受信任”不等于“不校验”。所有组件仍需校验数据类型、状态转换、资源预算和实际操作目标，以防普通软件缺陷和意外输入造成损坏。

### 3.2 不自动受信任

- 外部文件、归档、备份包、图片、数据库和其他待解析内容；
- 网络响应、重定向结果和第三方协议数据；
- 路径解析后的实际文件系统对象，尤其是 symlink、junction 和 reparse point；
- Renderer 传给主进程的标识符、状态引用和路径；
- 崩溃、并发、取消、重试和部分失败后的持久化状态；
- 第三方依赖、构建产物和发布包的实际内容。

这些边界按“可能出错或损坏”处理，不推定其背后存在恶意模型。

### 3.3 默认不纳入防护目标

- 恶意模型或恶意模型提供商主动窃取、外传或滥用数据；
- 已被攻陷的本地操作系统、用户账户、应用安装目录或受信任依赖；
- 当前用户故意利用自己的 Agent 破坏自己的机器或绕过自己设置的规则；
- 对传递给模型或模型提供商的数据做普遍的内容审核、秘密扫描、分类或脱敏；
- 除 5.5 节明确规定的命令 Shell 工具执行前授权外，通过网络主机白名单、私网阻断或普遍的逐请求确认来限制可信 Agent 的正常工作。

如未来需要企业多租户、零信任提供商、合规数据边界或不受信任插件市场，应先建立新的明确产品模式；不得把相关限制悄悄加入当前本地可信模式。

## 4. 安全目标

本项目优先保护以下性质：

1. **意图一致性**：执行对象、范围和副作用与用户目标及 Agent 的明确意图一致。
2. **损坏半径可控**：参数、路径或状态错误不能演变成大范围递归删除、跨项目覆盖或宿主数据破坏。
3. **可恢复性**：高影响修改优先使用暂存、回收站、revision、事务、备份或 rollback。
4. **状态一致性**：checkpoint、SQLite、JSON、文件系统和 Renderer 投影在崩溃、取消与并发下不会分叉。
5. **资源有界**：外部输入、模型输出、图片、归档、日志、网络响应和重试都有合理的时间、内存、磁盘及次数预算。
6. **发布完整性**：正式包只加载预期代码，并包含运行所需的完整依赖和资源。
7. **可观察性**：高影响操作、失败、回滚和恢复有足够日志用于定位，但日志不应无意记录完整凭据或无关敏感内容。

## 5. 审批原则

审批是意外损坏防护，不是模型行为许可系统。仅仅“由模型发起”“会执行代码”“会访问网络”或“会传递数据”都不构成审批理由。但对话工具访问模式可以要求无法结构化确定实际效果的命令 Shell 工具在执行前逐次授权。

### 5.1 决策维度

审批或二次确认应综合判断：

1. **意图清晰度**：当前任务是否明确要求该效果，Agent 是否明确说明目标；
2. **目标确定性**：展示目标与解析后的实际目标是否一致，是否存在通配符、路径逃逸、链接跳转或陈旧 ID；
3. **可逆性**：是否能可靠撤销、回滚或从 revision/备份恢复；
4. **损坏半径**：影响一个文件、一个项目、全部项目，还是项目之外的宿主数据；
5. **外部副作用**：是否产生难以撤销的发布、发送、付费、删除远端数据或账户级变更；
6. **异常程度**：范围或数量是否明显偏离当前任务，例如在小范围编辑中请求递归删除大目录。

### 5.2 默认无需审批

当意图与目标清楚、影响范围合理时，以下操作默认不因安全原因增加审批：

- 工作区内普通读取、搜索、创建和编辑；
- 通过专用受管能力运行已启用的可执行文件；命令 Shell 工具按 5.5 节的对话工具访问模式处理；
- 访问公网、私网、loopback 或本机开发服务；
- 使用已配置环境变量或凭据调用目标服务；
- 将任务所需内容传给模型提供商、MCP 或目标 API；
- 模型主动选择工具、创建辅助脚本或组合多步工作流；
- 可恢复、范围明确且符合任务目标的文件变更。

### 5.3 应提供审批或更安全执行机制

以下条件不是绝对禁止，但应优先缩小范围、展示实际目标、提供预览或回滚；仍无法消除意外损坏风险时再审批：

- 在“严格授权”或“允许只读”模式下，Shell 命令无法被完整确定为受支持的只读操作，或其实际目标不满足当前访问模式，且不符合 5.7 节的 Skill 脚本免审；未知语义不能按“没有发现危险”自动放行；
- 递归删除、批量覆盖、清空目录、重建数据库等不可逆或高损坏半径操作；
- 解析后的真实目标超出 Agent 和用户当前理解的项目或目录；
- 操作依赖来自 Renderer、模型或外部文件的未经验证 ID、路径、通配符或数量；
- 远端删除、公开发布、对外发送、购买或其他难以撤销的外部副作用，且当前任务意图不够明确；
- 实际影响范围与任务规模明显不相称；
- 应用无法可靠判断目标，或无法提供必要的事务、revision、回收站与 rollback。

即使需要审批，确认界面也应展示具体目标、范围和不可逆效果，避免只显示抽象工具名或泛化“允许/拒绝”。除 5.5 节明确规定的命令 Shell 工具逐次授权外，Agent 对明确目标的后续同类步骤不应被重复、机械地打断。

### 5.4 处理优先级

遇到高影响操作时，按以下顺序处理：

1. 先通过严格 ID、canonical target、资源上限、事务、revision、回收站或 rollback 消除程序自身可能造成的偏差；
2. 在满足当前对话工具访问模式后，若 Agent 意图清楚、实际目标一致且影响范围符合任务，直接执行；
3. 若仍存在目标或范围歧义，展示具体效果并请求一次有意义的确认；
4. 只有参数无效、目标无法安全确定或产品明确禁止时才拒绝执行。

除 5.5 节明确规定的命令 Shell 工具访问模式外，不得用频繁审批代替正确的受管路径、原子提交和恢复设计。

### 5.5 对话工具访问模式

- 命令执行能力的内部稳定 ID 是 `run_shell`，模型可见工具名取自实际可执行程序，例如 `pwsh`、`powershell`、`zsh` 或 `bash`；同一次运行的工具名、描述、语法提示和实际可执行程序必须绑定到同一个解析结果；
- “严格授权”：解析后目标位于项目目录外的文件操作必须在执行前暂停；Shell 在完整命令可确定为受支持的只读操作、实际文件目标均在项目范围内，或符合 5.7 节 Skill 脚本免审时自动放行，其他命令必须授权；
- “允许只读”是默认模式：项目外结构化文件读取可直接执行；Shell 在完整命令可确定为受支持的只读操作或符合 5.7 节 Skill 脚本免审时自动放行；无法确定的 Shell 调用和项目外结构化文件写入仍需执行前授权；
- “完整访问”是当前对话的显式选择：命令 Shell 工具和项目外结构化文件读写跳过执行前授权，但不改变工具能力、目标校验、资源限制或崩溃恢复规则，并可随时撤销以影响后续调用；
- `apply_patch` 与 `restore_file_edit` 的 `dry_run: true` 只解析、读取和计算预览，按结构化读取处理：严格授权仍要求项目外读取批准，允许只读可直接预览；正式执行独立按写入目标授权。预览不授予后续写入许可，checkpoint 必须绑定访问类型和全部实际目标；
- `write_file` 接收完整 UTF-8 内容，使用与补丁相同的路径授权、事务、变更记录和撤销机制；`overwrite` 默认 `false`，省略或传 `false` 时拒绝已有文件并以不可覆盖方式创建，只有显式传 `true` 才允许整文件替换。缺失父目录由事务管理，失败时仅清理本次创建且仍为空的目录；恢复重试仍独立确认；
- 应用配置修改工具在“严格授权”和“允许只读”模式下每次调用均需执行前授权；“完整访问”模式可跳过该授权；
- 首次执行授权只绑定当前工具调用，不得复用为外部操作状态不确定后的重试决定。恢复重试确认不受“完整访问”影响，也不能反向替代首次执行授权。

### 5.6 Shell 只读自动授权的范围

- Windows 使用 PowerShell 原生 Parser AST，不执行待分析文本；只接受可完整理解的常量内置 rg、受支持的读取 cmdlet 和只读管道。
- macOS 仅系统 `/bin/zsh` 支持静态内置 rg、系统 cat/head/tail/wc 和读取管道。使用 `shell-quote` 分词及 zsh 词法限制，不将 Bash AST 当作 zsh 语义证明。其他 Shell 和 Linux 在非完整访问模式下仍需人工授权。
- 普通只读分析不自动放行动态表达式、未知选项、脚本、写入、重定向、PTY 和保留进程。独立有界探针检查 zsh 启动配置、函数／别名、PATH、相关选项、工作目录及目标；不得禁用用户启动配置或向实际命令插入探针。
- 分析只判断原命令，不替换程序、参数、路径、引用或管道，不追加 rg 参数以取得授权。原有忽略规则保持不变；外部参数配置、链接跟随或预处理器等语义无法确定时请求授权。程序、运行库及只影响过滤的 ignore 配置不是任务文件目标。
- 自动授权依据和人工批准分别保存在 checkpoint，并绑定当前调用及原始参数摘要。派发前重新检查自动授权的环境、目标和访问模式；失败、超预算或目标变化时不得执行。此检查不是宿主沙箱，不保证覆盖后续并发变化或任意有状态启动脚本。

### 5.7 Skill 脚本免审

- Skill 页面全局“全部 Skill 脚本免审”和单个 Skill 的“脚本免审”默认关闭，任一开启即可为该 Skill 的受支持脚本调用豁免首次执行审批；设置保存在应用配置，不写入 Skill 文件。全局开启覆盖之后新增且可用的 Skill，脚本新增或修改不会使设置失效，不绑定内容哈希。
- 仍通过现有命令 Shell 工具执行，不增加 Skill 专用工具，不改变能力与工具细选绑定。免审仅适用于当前运行可用的 Skill；仅快捷可用的 Skill 必须由本轮用户显式调用，不能借全局免审授予子 Agent 自主使用权。
- 使用现有 PowerShell AST 或受支持的系统 zsh 静态分析，只接受单条“已识别执行器 + 普通脚本文件 + 字面量参数”。解释器选项只支持明确的文件执行形式；内联代码、模块执行、预加载、包装命令、额外命令、管道、重定向、动态展开、PTY 和保留进程继续普通审批。
- 绑定实际执行器、脚本真实路径、Skill 身份与真实目录、工作目录和原始参数。脚本必须真实位于该 Skill 内；受信任脚本的参数及内部副作用不做普遍扫描，本机制不是文件或网络沙箱。
- POSIX Shell 路径参数保留字面空白，由文件系统按顺序解析符号链接与 `..`，不得套用结构化工具的路径清理。脚本原始路径与解释器可能采用的规范化路径指向不同文件时，保留普通审批。
- 首次分析和实际派发前均读取当前免审设置并核验绑定，排队期间撤销或目标变化时不得凭旧豁免执行。原 Shell 命令不改写；完整访问和人工批准沿用原规则，结果不确定后的恢复重试仍独立确认。

## 6. 数据与凭据原则

- 模型和提供商处于信任边界内；不对发送给它们的数据增加普遍内容审查；
- Agent 可以使用完成任务所需的环境变量和凭据，不要求把凭据对模型统一隐藏为 opaque token；
- 不因目标是未知主机、私网或 loopback 而默认阻断或审批；本地服务访问是桌面 Agent 的正常能力；
- 对凭据的保护重点是避免无意写入普通日志、错误提示、持久化聊天展示或无关输出；
- 配置界面、日志和工具错误应避免意外展示与当前操作无关的完整秘密；
- 若用户明确要求数据隔离、脱敏或指定目的地限制，应把它作为该任务或未来独立产品模式的显式约束执行。

## 7. 实现边界

### 7.1 主进程与 IPC

- 主进程生成具有文件系统或持久化影响的内部 ID；Renderer 只引用已存在、可验证且属于目标实体的 ID；
- IPC 校验调用窗口、frame、参数类型、实体归属和合法状态转换；
- 校验是为防止 UI bug、陈旧请求和错误目标，不把 Renderer 普遍视作攻击者；
- 正式包只能加载预期的本地 Renderer，开发 URL 只在开发模式启用。

### 7.2 文件系统

- destructive target 必须在执行前解析并展示真实目标；
- symlink、junction 和 reparse point 不应被一律禁止，但不能让实际目标在校验后静默改变；
- 文件修改恢复存储在使用时绑定已配置的数据目录，不能在模块导入时提前固定默认目录；已创建的工具实例及单次异步操作保持同一存储根目录；
- 补丁按唯一精确上下文定位目标，歧义时拒绝整批预检，不以模糊匹配代替目标确认；
- 递归删除必须使用受管根目录、严格内部 ID、canonical containment 和深度不变量；
- 高影响修改优先采用原子替换、revision、回收站或可恢复事务；
- 只读操作不因模型可信问题增加审批，但仍受大小、数量、解码和超时预算约束。

### 7.3 Agent、工具与 Skill

- 项目及子 Agent 各自拥有能力配置。能力关闭时，其关联工具和上下文／执行环境注入同时关闭；工具细选不构成独立于能力开关的授权途径。子 Agent 默认仅按自身能力运行，项目可显式开启限制，使所有层级子 Agent 的能力与项目范围取交集；限制覆盖工具、上下文、应用环境注入及模型可见 Skill，项目仅快捷可用的 Skill 不授予子 Agent 自主使用权；
- 生效能力在每次运行开始时保存，授权恢复与崩溃恢复使用同一份配置。配置开关不改变 5.5 节的对话工具访问模式，也不构成宿主文件或网络沙箱。应用 `.env` 通过显式环境传给 Agent 的 Shell，不按项目修改共享的 `process.env`；MCP 连接及其服务环境由应用统一管理，项目仅筛选可见工具，不终止其他项目的共享连接；
- 项目及子 Agent 均可选择允许启动的全局子 Agent 定义；默认模式使用全局默认启用项，自定义模式可显式选用默认关闭的完整定义。根项目实际名单随运行配置保存并独立传给所有后代；子 Agent 自身选择随定义快照保存，每次运行解析为实际名单并与根项目范围取交集。恢复同一次运行不得因全局默认启用项变化而重新解析名单；选择范围与“限制子 Agent 能力”分别生效。自定义为空时不允许新建子 Agent；已启动的任务保留其配置并可继续监督；
- 项目“定制能力”关闭时，保存的能力选择、子 Agent 选择及能力限制不参与生效计算，使用默认配置且不注入项目提示词；开关不会删除已保存的配置。项目提示词是独立于项目信息能力的上下文段；

- Agent 可以按目标组合工具、编写和使用 Skill。Skill 不拥有专用工具：用户显式调用由宿主将完整 `SKILL.md` 原文和绝对路径封装为 `<skill>` 上下文，原用户消息与技能上下文分别发送，不做参数替换；技能目录直接提供当前可用技能的 `SKILL.md` 绝对路径，相对资源以 `SKILL.md` 所在目录解析；模型自主发现时按需读取说明。资源读取、修改和脚本执行仍使用当前可用的通用文件或命令 Shell 工具；结构化文件工具遵循项目外文件访问规则，命令 Shell 工具完成的读取、修改和执行均遵循 5.5 节的对话工具访问模式；
- 结构化工具的授权策略关注解析后的实际目标与损坏效果。Shell 按 5.5 节处理；仅对成熟解析器完整识别、受支持的命令语义自动放行，不把“未检测到危险”当作安全证明；
- 进程必须支持取消、超时、明确工作目录和可靠的参数传递；
- 不用提示词或工具描述代替删除范围、路径和事务不变量。

### 7.4 持久化与恢复

- LangGraph checkpoint 是 Agent 会话状态唯一真相源；
- 应用投影必须可从 checkpoint 或权威产品表重建；
- 跨 checkpoint、SQLite、JSON 和文件系统的高影响操作使用 staging、commit、rollback 或 revision switch；
- 恢复、取消和重试必须幂等，部分失败不能先破坏原数据再报告错误；
- 备份保留普通读写执行权限、空目录及目标也在备份内的链接，不恢复特殊权限位或复制外部链接目标。恢复流式校验 CRC，先解压普通项并验证链接目标在暂存目录内，再创建链接；不通过链接写文件。回滚持久记录阶段，重试不能删除已还原数据；
- 用户经确认主动重新生成、重发或删改消息历史时，应先停止受影响的本地执行；已停止调用的 `uncertain` 终态不能永久锁住历史替换。重新生成是用户发起的新运行，不是自动恢复旧工具调用；确认文案须说明已执行的工具操作不会撤销且可能再次执行，原有自动恢复重试确认规则仍适用。
- 外部副作用任务应在真实执行边界前持久化 intent，并在框架 task result 持久化前暂存精确结果；明确尚未越过边界的任务可自动继续，结果已持久化的任务直接回放结果；
- 已越过外部副作用边界但没有 durable result 时，只有具备稳定幂等语义的操作可有界自动重试；其他操作必须通过 LangGraph 原生 interrupt 展示已解析目标并确认是否重试；
- 恢复确认只处理崩溃或部分失败造成的重复执行不确定性，不得自行演变为按网络、MCP、Skill 或其他工具名称统一增加的 blanket HITL；它与 5.5 节明确要求的命令 Shell 工具执行前授权相互独立；
- 同一 task 的多次恢复确认必须具有持久序数，旧决定不得回答新一轮不确定性；并行与嵌套 task 的 intent、结果和确认必须按稳定 checkpoint namespace/task 身份隔离。
- 补丁在语法、上下文或预检阶段失败且未产生实际记录时，不返回预分配但不存在的恢复句柄；已有记录或副作用证据时保留可证实的操作引用和真实状态。记录暂不可读取不能等同于不存在，也不能因此保证尚未执行或恢复可用。

### 7.5 外部内容与资源

- 归档、图片、网络响应和数据库导入必须限制单项大小、总量、数量、压缩比、像素、并发和处理时间；
- Markdown 可以按产品需要加载远程和本地资源，不以模型不可信为由默认屏蔽；
- 资源加载失败应局部降级，不能阻塞整个应用或回退为无界内存复制；
- 本地图片预览不设源文件字节上限，这是本节单项大小限制的产品例外；原图通过 Electron 本地协议流式加载，不把完整文件转为 Base64 经 IPC 复制。发送图片附件仍限制每张 25 MiB；预览继续校验文件类型、图片尺寸与像素预算，并限制缩略图并发、输出及处理时间；
- 第三方解析库和打包依赖需跟踪已知漏洞与最终产物完整性。

目录树使用增量目录句柄及运行内短期游标，不全量读取、排序或按偏移重扫。每页最多 1000 项、约 1 MiB 条目文本和 2000 步遍历，并在 I/O 间检查约 1 秒的分页预算及取消；单次操作系统 I/O 无法保证被立即打断。默认及最大深度为 64，每个游标最多保留 1024 个待遍历目录、1 MiB 待遍历路径和一个目录句柄；全局最多 16 个游标，空闲 5 分钟后过期；取消或运行完成收尾时主动释放，仍有后台执行未结束时可能延后至空闲过期。超过展开边界的目录和不可访问项必须明确报告，不能冒充完整结果。游标绑定运行、根路径和深度，只能接续一次；分页及目录切换时复核目录身份与实际路径，发现目录或父级被替换、路径被链接重定向时关闭游标并要求重新开始。失效或重启后不静默退回偏移重扫。该操作仍属于现有受管工具范围。

### 7.6 受管工具执行与输出

- 普通内置工具、自定义工具和 MCP 共用受管执行层：最多 8 个执行槽，运行和等待合计最多 64 个。容量或本地修改互斥组繁忙时自动排队；排队不算派发，取消的等待项不得执行，实际执行结局确认前不释放槽位。
- 后台能力开启时，等待与执行合计超过 10 秒即返回可监督的调用编号。审批和效果准备在交接前完成；未派发的效果保持准备状态，真实派发时记录意图。等待用户输入时，已登记交接的调用可继续；不得借此新建调用或批准重试。晚到结果由受管调用记录保存，不依赖已结束运行的临时日志。
- 本地已开始的提交等待真实结局；MCP 取消不保证远端回滚，无法确认时标记不确定。MCP 保留服务器请求期限；工具列表刷新不主动中断同连接上的在途请求。
- Shell、HTTP 和自定义工具默认不限执行时间，仍支持取消及进程回收。后台输出增量持久化并保留至所属会话删除，不设置总输出字符上限。这是第 4、7.5 节资源有界原则对受管持久化输出的明确例外；不能退回无界内存缓冲，持久化失败必须中止执行并记录不确定结果。
- 单次模型读取输出最多 10000 字符；Shell 内联结果最多 120000 字符；HTTP 文本最多 1000000 字节，下载默认最多 1000000000 字节、可配置最大 100000000000 字节。没有输出不能单独证明任务卡死。

### 7.7 交互式终端

- PTY 使用已有受管执行层。后台工具为整体开关；启用命令执行或选中交互式自定义工具时提供 `write_call`。后台关闭时不提供 PTY，普通调用不能事后接入终端。
- 首次 Shell 命令及后续文本、按键、EOF 输入各自遵循当前访问模式；严格授权和允许只读模式逐次审批，完整访问可跳过，单纯调整尺寸无需授权。首次命令的批准不授予永久输入豁免。
- 输入绑定本会话调用 ID 和终端实例 ID；过期目标不得复用。成功只代表进入原生输入队列，不保证程序读取或执行完成。非幂等输入写入前记录效果，丢失确认不得自动重发；恢复重试独立确认。
- Windows 监督进程在派发握手前加入禁止 breakaway 的 KILL_ON_JOB_CLOSE Job，收到派发许可后才创建实际终端。应用持有 Job 句柄，取消、超时和退出沿用该回收边界。
- POSIX PTY 按整个 OS session 回收；复核启动身份，强制回收前有界暂停并重新枚举。无法完整核验时不得报告确认回收；不承诺覆盖程序主动另建的 session 或超出系统权限的进程。
- Ctrl+C 和 EOF 是终端按键，不保证结束程序；`cancel_call` 取消整个调用。PTY 不支持 `keep_processes`，重启不能重连旧实例，不自动重跑命令。
- 待持久化输出最多积累 128 Ki 字符／4096 条，达到即同步落盘。输入单次最多 16000 字符，每会话累计最多 1 MiB／4096 次；达到限额不影响取消，批量数据应使用文件。

### 7.8 自定义工具包

- `TOOL.json` 固定命令；有效默认、项目或子 Agent 能力显式选择可用工具。项目 `.agents/tools/` 优先于用户 `tools/`，同名只注册一个，新增项不自动启用。
- 命令在工具包目录执行，相对脚本及资源从此解析，目录不可用时拒绝执行。先解析程序与固定参数，再替换唯一独立的 `{{args}}`；业务参数经 JSON Schema 校验，不作为 Shell 源码，也不参与 `{{tool_dir}}` 替换。
- 专用工具启动不另加通用代码执行审批；不能借此改变通用 Shell 的授权规则。工具文件修改沿用文件操作规则；取消不承诺回滚副作用，不确定结果走现有恢复确认。
- 运行快照固定定义；用户工具按固定 ID 解析当前目录，项目工具保留快照目录。目录解析、占用、管理串行，进程使用目录时不能经设置改名或删除；改名与定义保存失败回滚。脚本及依赖按执行时内容运行，不另做指纹绑定。
- `.py` 入口验证后由共享环境探测器选择 Python 3；探测有超时、输出上限及进程回收，使用有效环境并执行返回的实际解释器，保留 Windows `py -3` 的版本选择。成功结果按环境与工作目录短期缓存，不自动安装解释器或重跑业务脚本试错。显式解释器按配置执行。
- 内联 stdout 最多 524288 字符、stderr 最多 120000 字符，超限标记截断。交互模式默认关闭且依赖后台能力，后续输入遵循 7.7 节；不限时为 `0`，正整数秒指定期限。
- 示例启动时镜像至 `tools_examples`，不直接注册。导入先校验定义、名称／ID 冲突及复制预算，暂存后发布，失败回滚本批文件与排序，不覆盖已有工具。格式与使用见[自定义工具](CUSTOM_TOOLS.md)。

## 8. 严重级别

- `P0`：无需恶意模型参与，普通输入、程序缺陷或陈旧状态即可触发大范围且不可逆的宿主文件或核心数据删除；必须阻断发布。
- `P1`：可能导致不可恢复的数据损失、跨目标误修改、checkpoint/持久化分叉、恢复破坏原数据或正式包核心功能失效。
- `P2`：影响正确性、资源、费用、交互可靠性、可访问性或局部可恢复性，但通常不造成大范围永久损坏。
- `P3`：主要影响维护性、诊断能力、依赖卫生或规则一致性。
- `产品决策`：某项能力只有在“模型/提供商不可信”的前提下才构成风险，而当前产品明确接受该信任前提；记录结论，不列为漏洞或发布阻断。

严重级别必须按真实可达路径、默认配置、影响范围和恢复能力评估，不能只按“理论上可执行代码”“理论上可发送秘密”或通用漏洞类别套级别。

## 9. 审计判定流程

每条安全发现必须依次回答：

1. 不假设恶意模型或恶意提供商时，问题是否仍可发生？
2. 这是 Agent 为完成明确目标而有意产生的效果，还是实现偏离了该意图？
3. 实际损坏、数据丢失、费用或外部副作用是什么，是否可恢复？
4. 触发是否只依赖普通输入、崩溃、并发、陈旧状态或合理误操作？
5. 现有审批是否能展示真实目标和范围，还是只按工具名机械打断；若为命令 Shell 工具，是否属于 5.5 节明确的访问模式？
6. 根因应由校验、受管路径、事务、revision、资源预算或可取消性解决，还是确实需要用户确认？
7. 结论是 `P0`—`P3`、产品决策，还是不成立？

审计报告必须把“已确认事实”“产品信任假设”“推断影响”和“建议改动”分开。若发现只在零信任模型下成立，应明确标为产品决策，不得继续作为发布阻断项。
